# CourtIQ studio checkpoint

CourtIQ now opens directly into a light basketball world on `/` and `/lab`. The first executable problem is **High P&R → low-man tag → weakside lift / skip**. A coach can run his answer against a reacting opponent, edit a defender's rule or floor target, compare the resulting worlds, search for a counter, fix the exposed responsibility, retest, and save/teach the exact answer. The public Lab requires no film, tracking hardware, analyst, account or connected service.

## Material changes

- **Reusable art production:** editable Blender athlete and gym sources, reproducible exports, thirteen basketball actions, high/tactical mesh LODs, native glTF validation and documented CC0 source provenance. Normal athletes and analytical bodies have separate responsibilities.
- **Spatial coaching:** selected defenders receive body-aware contextual controls. D3's floor tag rail changes executable policy; D5 has contextual screen coverage. Frozen floor demonstrations become accelerating movement targets with explicit release cues. Two bounded conditional basketball sentences add roller-depth and lift-rise rules.
- **Executable opposing systems:** observations activate defensive obligations and offensive reads/counters. Lift, reject, short roll, re-screen and subsequent catch reads can connect. A separate baseline-drive fixture checks reuse beyond the P&R content.
- **Break Mode:** only actual tested trajectories appear; the selected possession plays from the start and freezes at an executable vulnerability. Fix opens coaching on the responsible defender. Break it again replays the prior opponent against the revised defense before searching further.
- **Two ways of seeing the same world:** a reversible 450 ms X-ray transition replaces normal rigs with analytical envelopes. Responsibilities, actual flight segments, sampled future reach and conflicts share engine snapshots. Compare synchronizes prior defensive ghosts, trajectories and spatial divergence in one court.
- **Physical execution and performance:** acceleration, braking, bounded turning, body avoidance, fixed-endpoint ballistic flights, body intersection and catch support affect execution. Contact stops the possession without inventing its outcome. A worker handles bounded search; frozen rendering is on demand, with live draw limits, adaptive scale/LOD, instancing and a bounded immutable replay cache.

## A real modeled tradeoff

In the default answer, changing D3 from deep tag to shallow tag at 0.75 s closes the modeled lift opening by **0.10 s** and opens the roller by **0.15 s**. The opponent's first read changes from lift to roll. Earlier frames stay equal. Later drive exposure can remain: the edit moves the tradeoff rather than universally solving the defense.

The comparison in the main studio browser loop uses additional custom reads and a later movement cue. Its measured windows remain equal, and the UI reports that honestly. A separate default-answer comparison demonstrates the consequential tag experiment.

## Computed and authored

Movement integration, observed activations, possession history, flight/contact witnesses, geometry-derived windows, arrival estimates, replay comparisons and finite search results are computed. Basketball policies, thresholds, preferred reads, animations and physical/personnel parameters are authored. They are not measured athlete calibration.

A geometric opening before a permitted read is a forecast. Break evidence requires an executable read or an ongoing selected drive. Arrival assumes an unobstructed route. Analytical bodies approximate human reach; detailed rendered animation cannot change physical evidence. The engine does not predict shooting percentages, wins, fouls, deflections or turnovers. A finite search is not an exhaustive proof that a defense holds.

## Remaining acceptance gates

The sports-game reference remains ahead of this deliberately stylized asset and animation checkpoint. Foot planting, screen bracing, cloth and faces need further art work. Floor-disc avoidance is not a legal-screen or contact-force solver. Two conditional sentences and supported templates are the current custom vocabulary; arbitrary basketball language and complete philosophies remain architecture goals.

Cloud Chromium/SwiftShader verifies functionality, not school-laptop frame rate. Run the physical integrated-GPU protocol before claiming hardware acceptance. A real high-school coach must still change a game-plan answer, want to return, and ask to use CourtIQ before the next game. That founder success criterion has not been established by automated checks.

## Run this branch

Branch: `feat/courtiq-strategy-lab`. Use Node 22 and pnpm 9, then from the repository root:

~~~bash
pnpm install
pnpm --filter @courtiq/web dev
~~~

Open `/lab` on the local development server. Start with the default answer, run to the tag, choose D3 and a shallower tag, rerun and Compare. Then try Break → Fix → Break it again → Save / teach. The final commit identifier is included in the founder handoff.
