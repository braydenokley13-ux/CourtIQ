# Independent Break Mode critique — studio phase

Status: static review of `BreakMode.tsx`, its styles, the preview contract, and the evolving renderer on 2026-10-05. Root integration and the new studio browser loop remain unverified. The earlier 18 browser checks belong to the previous interface. The seven-check production runner was prepared and held; it has not run.

The branch audition is the stronger first implementation because it preserves an entire possession's causal lead-in. A pressure lens would be attractive for teaching one familiar read, but the present search changes initial conditions. Aligning alternate worlds at a shared intermediate moment would imply a stateful fork that the runtime has not made. For the audition, each trace must remain visibly a completed alternate replay. Four overlapping traces do not automatically communicate four legal choices available to the current ballhandler.

## Primary correctness risks

1. **Different replays can resemble one branching possession.** Keep the tested-replay wording, associate each trace with its actual player and basketball intent, and deduplicate coincident geometry. Never fan identical paths apart for legibility. Promote one complete selected replay before playback. A permission change must not be described as an executed reject, re-screen, or short roll unless the actual events confirm activation.
2. **The parent owns the truth of the freeze.** `BreakMode` trusts `phase="frozen"` and prints the report's witness time, independently of the current clock. Require actual playback to reach that exact executable witness. Pausing or seeking before it must show replay inspection, rather than “Frozen at first exposure.” Cancel the worker and the delayed selection-to-play transition on exit, reset, content changes, loading a saved answer, and a replacement request. An old callback must not move the new world.
3. **Execution unresolved must remain a separate outcome.** The component correctly gives failed flight/catch/boundary execution an amber outcome and an Inspect action when there is no witness. That result must remain inspectable through search, selected preview, full playback, freeze, Why, and the paired retest. A selected candidate can have no opening; selection alone is not evidence of exposure. A conditional witnessed opening must retain its conditional wording at every stage.
4. **Comparison must preserve the old defense.** A revised D3 movement cue belongs only to the new answer. The ghost world must use the previous defensive answer and defensive movement cues against the selected current opponent. Both worlds share seed, initial geometry, offensive interventions and disclosed movement assumptions before claiming an isolated defensive comparison. A synchronized clock alone does not establish paired inputs.

## Code-level findings sent to implementation owners

- `latest = candidates[candidates.length - 1]` can describe an older callback when a final selected preview upserts an earlier candidate id. Track actual arrival order or the latest callback explicitly.
- The caption's `branchEnter` animation fills forward with `opacity:1`, overriding the held route's `.55` opacity. Use a fade grammar that remains true after the animation finishes.
- The renderer resets one global route-animation age whenever the `candidatePaths` array reference changes. A streamed arrival can restart old route reveals and restore faded held routes. Keep parent input identity stable and retain a per-candidate arrival age.
- X-ray currently concatenates pass/shot samples around the inspected time into one line. Near two consecutive flights, that can connect them across a held-ball interval. Split by actual flight identity so every visible arc segment represents that flight.
- The current quality adaptation reads synchronous CPU submission duration and operates during Normal playback. That misses GPU-bound rendering and X-ray/Break pressure. Frame and mode evidence are needed before making performance claims.

## Spatial and accessibility acceptance

The new camera should make the screen, weakside help, lifting receiver, and selected breakdown the largest useful content. The goal is a readable basketball problem, rather than showing all gym architecture. A fixed 290 px search caption or 250 px mobile caption can occupy much of that problem. Check actual overlaps with athletes, ball, screen encounter, option target, timeline and coaching card in every phase. The frozen callout should attach to its limiting defender while leaving that player's body and the threatened receiver visible.

Route color should be reinforced by line style and plain wording. The current amber conditional styling and unresolved text are useful. A touch target of 34 px is tight; aim for at least 44 px on the primary Fix, replay, exit and attack-again actions. Keyboard users need a discoverable entry point, visible focus, exit during the selection dwell, and a dependable return of focus. Announce phase changes and outcome once; do not flood a live region with every replay completion or clock tick. Reduced motion should shorten the route emphasis and analytical transition while preserving the same evidence and actions.

## Comparison and X-ray directions to evaluate independently

**X-ray A — porcelain analytical athletes.** Prefer strong ownership and shape readability. Inspect whether clean envelopes, projected responsibility lines and sampled future positions remain distinct from the normal body's art rig. Selection, team identity, ball ownership and grounded feet must survive the transition.

**X-ray B — spectral rig and vectors.** Prefer explicit orientation, reach, velocity and timing. Thin bones and translucent envelopes can disappear on a pale court or become a dense line bundle. Check contrast at laptop size and mobile scale before calling it an improvement. Compare A and B at the same seed, clock, camera, player and layer.

**Comparison A — synchronized ghost defense.** Show the prior defense in the same environment while the current answer is solid. The coach should be able to trace D3 divergence, D4's changed responsibility and the affected passing/drive opportunity. Hide unchanged ghosts to protect clarity, but label which world each representation belongs to.

**Comparison B — time-aligned world morph or scrubber.** Keep one displayed representation at a time and interpolate presentation between the two stored worlds. This can reduce clutter, but intermediate geometry must be labelled as a visual blend, not an executed or basketball-valid third answer. Simulation evidence and displayed numbers remain anchored to an actual endpoint world.

A disagreement worth preserving: spectacular branch audition should stay optional once the coach already knows the breakdown. A direct “retest this same attack” route to the paired possession may serve repeated coaching better than replaying the full visual audition every time.

## Integrated source follow-up

The owners addressed the original static findings before the new studio browser run: selected audition paths now use the selected replay rather than truncating it out of a four-path set; search routes use a deduplicated bounded subset; candidate aging is per ID; held caption opacity is no longer overridden by animation fill; flight segments are split at possession/flight changes; adaptive quality measures actual draw cadence across active modes. Root changed scrub/play handling so earlier inspection exits the frozen phase and restores the exact witness stop on replay. These are verified source changes; their actual UI behavior remains subject to the studio runner.

The accessible floor-tag marker is projected from the real renderer target. Mouse input passes through to the Three.js rail interaction; keyboard arrows provide a policy-depth alternative. The independent runner observes native worker messages and records phase transitions without an application state mutation hook.
