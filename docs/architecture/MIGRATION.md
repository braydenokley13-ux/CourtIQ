# Foundation migration decisions

Baseline: merged main `1eb6a3309aa5934136f42b1c02ebdf52934848f1`. Its tree includes all 31 latest product commits from the branch the founder merged. The repository was clean before migration. Preservation refs are `preservation/courtiq-before-foundation-2026-10-06` and `archive/courtiq-merged-main-2026-10-06`. Git history is the archive; no legacy application tree is retained.

The observed production alias served the old training application while recent main/preview deployments failed before Next compilation on a deleted database hostname. The Vercel build attempted SQL deletion, schema push accepting data loss and production seeding. These build edges were removed; the intentionally deleted Supabase project was neither recreated nor replaced.

Sol specialists designed and migrated the engine, program knowledge and retirement/platform workstreams. Independent Astra reasoning considered an alternative separation and fresh Sol/Astra critiques attacked the target before implementation. Root adjudicated one architecture rather than combining incompatible designs. Luna archaeology classified routes, dependencies, assets and deployed behavior; browser QA exercises real product controls. UltraCode was not available as an executable or plugin in this environment, so no invocation is claimed.

## Decisions

- One pure basketball package with distinct domain/content/simulation/query/program modules. Browser workers, storage and replay caching stay in the application.
- Canonical serializable materialized execution input, with family-specific coaching recipes as editing provenance. Engine/content/query identity follows accepted evidence.
- Generic interpreter with bounded expressions and authored ordering. High P&R names and first-read preferences remain in its content compiler.
- Baseline drive/drift uses independent roles/opportunities and the same kernel, not relabeled P&R or a second simulation.
- Exact execution snapshots and immutable accepted history. Teach pins a version; edits and retests create versions.
- One transactional IndexedDB repository, revision CAS, atomic migration/import and preserved recovery sources. No silent volatile fallback or timestamp-based overwrite.
- Portable replay-from-start bookmarks/forks. A partial display frame is not a supported checkpoint.
- Existing world and athlete quality retained, with extracted fallback closure and local fonts. X-Ray arrival coloring consumes domain samples and Compare uses the correct assumptions.
- Frozen install, deterministic local content manifest, plain build/deploy and zero database writes.

## Intentional behavior corrections

The merged engine used a literal offensive rule ID as a movement guard. That guard worked for the current hero; the frozen comparison confirms preserved movement. Authored identifiers now remain opaque, with rename-invariance tests covering both fixtures. A tag guide reconstructed policy memory from a display frame and could differ from the delayed engine obligation by 1.859 m at 0.75 seconds. It now derives from the recorded policy evaluation. Arrival coloring formerly used a separate shader motion estimate and comparison bodies used default assumptions; both must consume the experiment's domain values.

The responsibility-conflict query previously used baseline speed and acceleration even for faster personnel. Two feasible forward-path regressions demonstrated false impossibility claims. The optimistic travel bound now retains the defender's own capability while still omitting obstacles and turning; the frozen hero comparison remains unchanged.

Former dual local stores and name-based updates are replaced by stable program entry/version identity. Old answers lacking recorded execution provenance remain legacy-unverified and need an explicit current-engine retest. Stale Break evidence is invalidated on material experiment changes and accepted evidence carries its base/candidate relationship.

Independent capacity review found that the initial 8 MiB limit counted a heavily indented backup during every durable save, allowing only about 11 ordinary versions or five versions with one frozen Break each. Compact JSON and a shared 128 MiB durable/portable limit remove that premature ceiling without changing the execution schema or weakening immutable evidence. A 24-version history with frozen Break inputs has a roundtrip regression. Representative compact growth predicts about 678 ordinary or 268 one-Break versions across the program, subject to the 500-version-per-entry limit. Large-history quota and speed remain device-dependent; paging and content deduplication belong to future repository/wire adapters, not a replacement basketball model.

## Alternatives and consequences

A cleaned-up P&R script with a second baseline script would preserve the present demo cheaply but make every new basketball problem another engine. The selected interpreter instead executes authored actions, obligations and reads. Family compilers retain basketball-specific vocabulary and policy formulas; adding content does not require dispatching on its family in the kernel.

A configuration-only save would be smaller, but future compiler changes could silently alter an accepted answer. An accepted version stores the materialized execution input and provenance. Its editing recipe is optional. This costs storage and requires compatibility validation; unsupported inputs remain exportable without being replayed by an incompatible engine.

Restoring from a display frame would make forks fast but omit delayed observations, action memory, contact and flight state. Replay-from-start forks preserve the exact prefix with a simpler portable contract. Long film possessions may later justify a complete, versioned checkpoint format with equivalence tests.

LocalStorage or an automatic in-memory fallback would simplify browser storage but cannot provide atomic program/import/migration writes or dependable concurrency control. IndexedDB provides transactions and revision compare-and-swap. A blocked or failed store is visible to the coach, and existing bytes remain recoverable.

A new hosted database would hide deployment coupling while retaining it. Local content plus an application repository port makes cloud optional. Sync will need explicit conflict handling and identity decisions; no cloud provider, authentication or distributed merge behavior is promised by this commission.

## Extension seams

Future cloud: implement the program repository and synchronization adapter; preserve stable IDs/lineage and resolve divergent history explicitly. Future offense: author validated actions, observations, obligations and read graphs; extend primitives only when a mechanism cannot be expressed. Future film/tracking: translate observed evidence into domain values with provenance rather than making rendering or a vendor payload canonical. Future AI: propose validated content or coaching recipes with explicit acceptance; deterministic basketball remains independent of models and providers.
